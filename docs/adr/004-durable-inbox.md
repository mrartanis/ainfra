# ADR 004: durable server inbox

2026-10-22, по запросу владельца. Синхронный пересчёт CVE превышал 30-секундный HTTP deadline при первичном подключении реальных хостов. Сетевые повторы снова запускали ту же дорогую транзакцию.

API проверяет токен, scope/instance, структуру, размеры, часы и известные конфликты receipt. Затем записывает principal без credentials и полный отчёт в таблицу `agent_inbox`. Только успешный SQLite commit с `synchronous=FULL` разрешает ответ HTTP 200 со статусом `queued`. Невозможность сохранить или переполнение возвращает 503; недействительные данные не получают успешный ответ.

Inbox находится в отдельном SQLite WAL-файле `DB.inbox`, переопределяемом `--inbox-db`. Таблица в основной базе не изолировала бы приём: SQLite допускает только один writer, а пересчёт findings держит write transaction. Inbox не меняет основную схему и не хранит токены.

Один worker выбирает отчёты по времени получения, сохраняет попытку и состояние `processing`, затем выполняет существующий ingest с лимитом пять минут. Только после commit инвентаря удаляется payload. Сбой между двумя commit безопасен: receipts с hash и sequence исключают двойное применение. Рестарт возвращает незавершённые `processing` в `pending`. File lock запрещает два процесса-владельца одного inbox.

Временные ошибки оставляют payload и повторяют обработку через 30 секунд. Ошибки identity/instance/структуры/конфликта переводят строку в `rejected` и оставляют её для диагностики. Лимит — 1000 сохранённых отчётов либо 256 MiB суммарного payload; rejected тоже занимают лимит. Ошибки публикуются только как безопасные коды. Полные payload недоступны через HTTP.

`GET /api/v1/ingest/queue` доступен reader/editor/admin: количества, байты и до 100 старейших строк с node_id, received_at, состоянием, попытками и кодом ошибки. Агент остаётся write-only. Получение в inbox не обновляет last_report или время пакетного снимка; эти поля меняются после обработки. `received_at` очереди — время приёма, `received_at` узла — время применения.

Backup сначала снимает inbox, затем основной инвентарь. Команда `infra-server backup --db DB --output COPY` создаёт также `COPY.inbox`, если inbox существует. Согласованность обеспечивается безопасным replay строк первого снимка против более поздней основной БД. Нельзя копировать открытые WAL-файлы обычным cp. При restore сервер остановлен; восстановить оба файла, сохранить старые файлы до замены. Старый server binary не обработает inbox: при откате нельзя терять оставшуюся очередь.
