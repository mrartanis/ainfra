# ADR 003: ограниченное хранение на сервере

По просьбе владельца ограничиваем глубину и размер хранения. Текущий инвентарь и активный snapshot каждого feed заменяются, а не накапливаются. Квитанции отчётов и audit-events хранятся 90 дней, максимум 100000 каждого типа. Сохраняются 20 последних ревизий документа и отдельно одобренная ревизия. Закрытые findings удаляются через 90 дней от `resolved_at`: повторная оценка/heartbeat не продлевает этот срок. Повторное открытие сбрасывает дату закрытия; для старых записей без неё используется сохранённый `last_evaluated`. Открытые findings, документы, ручные сущности и действующие credentials автоматически не удаляются.

Все значения — флаги сервера. Очистка при старте и каждый час, также `infra-server prune`. Результат и политика доступны через `/api/v1/settings`. Квитанция может быть удалена, но sequence узла сохраняется: поздний повтор не откатывает snapshot.

`--max-db-mib` (1024 по умолчанию) задаёт SQLite max_page_count, при заполнении транзакция завершается ошибкой. Освобождённые страницы переиспользуются. WAL checkpoint после очистки; journal_size_limit 16 MiB ограничивает оставшийся WAL после checkpoint, не максимальный размер активной транзакции. Нужен запас диска на WAL и backup: max-db-mib не является квотой всего каталога. Резервные копии — отдельные файлы с собственной политикой оператора.
