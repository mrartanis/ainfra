# ADR 002: best-effort доставка инвентаря

Уточнение владельца в ходе реализации: гарантированная доставка старых наблюдений не требуется. Заменяет пункт ТЗ о дисковом spool.

Один запуск агента собирает свежий отчёт и делает максимум три попытки доставки с тем же report_id, паузы 1 и 2 секунды. После неудачи завершает работу с ненулевым exit code и отбрасывает отчёт. Следующий timer собирает новые данные. На агенте нет очереди или replay старых отчётов.

Уточнение владельца 2026-10-22: сервер сохраняет принятые отчёты в SQLite и обрабатывает асинхронно; см. [ADR 004](004-durable-inbox.md). Ответ 200 означает durable receipt, а не завершённую оценку CVE. Это не добавляет дисковый spool на агент.

На диске остаются identity в конфигурации и восьмибайтовый по смыслу sequence (десятичный файл): это порядок наблюдений между перезапусками, а не гарантия доставки. Счётчик атомарно увеличивается до сбора. Пропуски допустимы. Сервер отвергает откат; потеря state требует явной reenrollment. Отдельный process lock исключает одновременные сборы.
